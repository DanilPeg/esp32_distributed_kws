# Hash KWS firmware variants

The training notebook (`code/training/hash_ensemble/hash_ensemble_train_colab.ipynb`)
exports one independent firmware bundle per ensemble variant:

| Variant | Output dir                                       | PW codebooks (per block)          |
|---------|--------------------------------------------------|------------------------------------|
| `ens_a` | `code/firmware/hash_kws_runtime_ens_a/`         | (1024, 1280, 1536, 1792)           |
| `ens_b` | `code/firmware/hash_kws_runtime_ens_b/` (= base) | (1280, 1536, 1792, 2048)           |
| `ens_c` | `code/firmware/hash_kws_runtime_ens_c/`         | (1536, 1792, 2048, 2304)           |

The Arduino sketch (`code/firmware/micro_speech_sim/micro_speech/`) always builds
from `code/firmware/hash_kws_runtime/`. To flash a specific variant, copy the
right bundle on top of the active runtime first:

```powershell
pwsh -File code\scripts\select_hash_kws_variant.ps1 -Variant ens_b
```

Then open Arduino IDE → Sketch → Verify/Upload as usual. The 3 boards in the
distributed demo each get a different variant (`ens_a` on node 1,
`ens_b` on node 2, `ens_c` on node 3), and the master role runs the
ensemble aggregator from `code/firmware/hash_kws_aggregator/`.

The Aggregator reads calibrated temperatures and learned weights from
`code/training/hash_artifacts/hash_ensemble/aggregator_params.h` (also
auto-generated by the notebook). Copy that header next to the sketch (or use
an `#include` with an absolute path) when you want the calibrated /
learned-weight aggregation paths instead of plain `mean_logits`.
