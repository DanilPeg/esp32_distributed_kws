# Hash KWS Master with on-board dashboard

Standalone master sketch for the 4th ESP32. Serves the live dashboard
itself — no host PC, no Python scripts, no FastAPI. Any laptop or phone
on the same WiFi opens the master's IP and watches the ensemble live.

## How it works

```
  3× ESP32 (mics + KWS)            1× ESP32 (master, this sketch)
  ┌──────────────┐                 ┌──────────────────────────────┐
  │ ens_a node 1 │  ESP-NOW pkts   │ ESP-NOW recv                 │
  │ ens_b node 2 │  ──────────────►│  → hash_ensemble_aggregator  │
  │ ens_c node 3 │  (12 int8 logits)│ → AsyncWebServer + WebSocket │
  └──────────────┘                 │  → http://<master-ip>/       │
                                   └──────────────────────────────┘
                                        ▲
                                        │  any browser on the same WiFi
                                        ▼
                              your laptop / phone / projector
```

ESP-NOW packet layout matches `code/firmware/micro_speech_sim/micro_speech/micro_speech.ino`
exactly — same magic, version, CRC16, and `int8 logits[12]`.

## Required Arduino libraries

Install via **Library Manager** (Sketch → Include Library → Manage Libraries):

| Library | Author | Notes |
|---|---|---|
| `ESP Async WebServer` | mathieucarbou | The fork that supports esp32 core 3.x. Search "ESPAsyncWebServer mathieucarbou". |
| `Async TCP` | mathieucarbou | Pulled automatically as a dependency, or install directly. |
| `ArduinoJson` | bblanchon | ≥ 7.0 |

> Do **not** install the older `me-no-dev/ESPAsyncWebServer`. It does not
> compile against esp32 core 3.x and will throw template errors.

Board settings (Tools menu): same as the rest of the project — ESP32S3 Dev
Module, USB CDC On Boot Enabled, Flash 16MB, PSRAM OPI PSRAM,
240 MHz, Upload 921600.

## Configure WiFi credentials

Edit the top of `hash_kws_master_web.ino` (or pass as build flags):

```cpp
#define HASH_KWS_STA_SSID "your-router"
#define HASH_KWS_STA_PASS "your-password"
```

If `HASH_KWS_STA_SSID` is empty, the sketch falls back to AP mode
(`esp32-hash-master` / `12345678`) so a botched config still gives you
something to connect to.

## CHANNEL — most common pitfall

ESP-NOW between nodes and master must use the same WiFi channel. When the
master joins a router, its radio is locked to the router's channel. The
inference nodes don't talk to the router — their channel is set at compile
time via `HASH_KWS_ESPNOW_CHANNEL`.

**They must match.**

How to find the router's channel on Windows:

```powershell
netsh wlan show interfaces
```

Look at the `Channel` line. Typical values: 1, 6, 11 on 2.4 GHz.

Then build all 4 sketches with the same channel:

```
-DHASH_KWS_ESPNOW_CHANNEL=<that channel>
```

If you don't change anything, default channel is 1 — pick a router on
channel 1, or move it to 1 in router admin, or accept that you have to
reflash inference boards too.

The master sketch logs a loud warning at boot if `WiFi.channel()` differs
from `HASH_KWS_ESPNOW_CHANNEL`.

## Other build flags

```text
-DHASH_KWS_AGG_MODE=0          # 0=mean_logits (recommended), 1=temperature_scaled, 2=learned_weights
-DHASH_KWS_WIFI_MODE=1         # 1=STA (default), 0=AP
-DHASH_KWS_AP_FALLBACK=1       # if STA fails, run as AP so demo still works
-DHASH_KWS_AP_SSID=\"esp32-hash-master\"
-DHASH_KWS_AP_PASS=\"12345678\"
```

`HASH_KWS_AGG_MODE` chooses the aggregator. Calibrated parameters live in
`aggregator_params.h` (auto-generated by the training notebook). On the
KWS data all three modes produce ~0.9425 top-1 ±0.06 p.p., so
`mean_logits` (no `exp()` on chip) is the default.

## Boot output (what to expect)

```
hash_evt kind=boot node=master role=master_aggregator channel=1 agg_mode=0 wifi_mode=1
[wifi] STA connecting to "your-router"...
[wifi] STA connected, ip=192.168.0.42 rssi=-58 channel=1
[http] dashboard at http://192.168.0.42/
hash_evt kind=espnow phase=init status=ok node=master mac=XX:XX:XX:XX:XX:XX
```

Open `http://192.168.0.42/` in any browser on the same WiFi.

When inference nodes start sending packets you see:

```
hash_evt kind=fusion node=master label=yes score=4736 margin=2048 voters=3 mode=0 packets=14 rejected=0
```

…and the dashboard updates in real time.

## Dashboard

Single page, no frameworks. Three node tiles for ens_a / ens_b / ens_c
with last label / score / margin / packets, a counters strip
(fusion total, packets, rejected, aggregator mode, uptime), and a
fusion-history list (newest first, ~50 entries).

Everything is pushed via WebSocket — no polling, ~1 KB/s when active.

## REST endpoints (handy for scripting)

- `GET /` — the dashboard HTML.
- `GET /health` — JSON liveness probe with current counters.
- `WS /ws` — live event stream (snapshot on connect, then `node` and
  `fusion` deltas).

## Troubleshooting

**Browser shows "live" but no node tiles update.** Channel mismatch. Read
the boot log: if `WARNING: router channel X differs from compiled ...`
shows up, you have to reflash with the right `HASH_KWS_ESPNOW_CHANNEL`.

**Master never connects to WiFi.** Check SSID/password, check the router
is 2.4 GHz (ESP32-S3 has no 5 GHz radio). After 15 s of failed attempts
the sketch falls back to AP mode and lets you connect to
`esp32-hash-master` to debug.

**`packets=0` but `rejected>0`.** Inference nodes are sending, master
sees raw bytes but rejects them. Either CRC mismatch (rebuild master and
inference from the same checkout) or struct layout drift between
`micro_speech.ino` and this sketch's local copy of `HashKwsEspNowPacket`.

**Dashboard tiles flicker between "online" and "stale".** Inference node
isn't broadcasting reliably. Look at that node's USB Serial — likely
`hash_evt kind=espnow phase=tx status=fail` lines.
