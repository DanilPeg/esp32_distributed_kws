# Как работает наш агентный фреймворк: память, эволюция и контроль качества

![Framework cover](/file?path=images/figures/articles/cover_agents.svg)

## Аннотация
Этот текст фиксирует, **как устроена наша рабочая инфраструктура**: память (BIBLE/журналы), эволюционный цикл, очередь задач, связь с Telegram, веб‑портал и контур аудита. Цель — сделать систему прозрачной и управляемой: любое действие должно иметь след в логах и артефакт, а изменения кода — выполняться в отдельной ветке с ручным решением о merge.

![Agent loop](/file?path=images/figures/articles/diagram_agent_loop.svg)

## 1. Принципы
1. **Доказуемость**: любое утверждение опирается на лог, эксперимент или артефакт.
2. **Прозрачность**: нет «магии» — только формальные файлы состояния.
3. **Разделение ролей**: агент исполняет, оркестратор принимает финальные решения.
4. **Безопасные изменения**: правки кода выполняются в отдельных ветках.

## 2. Основные компоненты
### 2.1 BIBLE — конституция агента
Файл `BIBLE.md` фиксирует:
- правила работы,
- структуру репозитория,
- требования к логам и доказательности,
- базовые команды для Telegram.

BIBLE — всегда источник правды для поведения агента. Если правило не прописано — оно не считается обязательным.

### 2.2 Журналы и память
Папка `notes/Journal/` — это линия времени:
- прогресс‑лог с решениями,
- чекпоинты,
- ежедневные summary.

Это «след», по которому можно восстановить контекст без потери деталей.

### 2.3 Агент runtime
Ключевые файлы:
- `code/agent/runner.py` — цикл эволюции.
- `code/agent/executor.py` — подготовка задач и запуск Codex.
- `notes/Journal/agent/queue.json` — очередь задач.
- `notes/Journal/agent/events.jsonl` — события.
- `notes/Journal/agent/tasks/<id>/` — workspace по задаче.

### 2.4 Telegram интерфейс
Telegram — это быстрый интерфейс управления:
- `/evolve` — управление эволюцией,
- `/agent` — статус,
- `/task` — добавление своей задачи.

### 2.5 Веб‑портал
Портал дает read‑only доступ:
- BIBLE,
- Research/PDF,
- Summary,
- Roadmap,
- статус эволюции.

## 3. Эволюционный цикл
Цикл работает по расписанию (сейчас каждые 15 минут):
1. Проверка health.
2. Планирование новой задачи (review‑block).
3. Подготовка задач executor‑ом.
4. Запуск Codex exec.
5. Авто‑закрытие задач.
6. Отчет в Telegram.

## 4. Жизненный цикл задачи
**Шаги по задаче:**
1. **Enqueue** — задача попадает в `queue.json`.
2. **Prepare** — создается workspace, context pack, prompt.
3. **Execute** — запускается `codex exec`.
4. **Report** — появляется `report.md`.
5. **Close** — задача завершается автоматически.

**Артефакты в `tasks/<id>/`:**
- `task.md` — описание и рамки.
- `context_pack.md` — сжатый контекст.
- `prompt.txt` — стартовая инструкция.
- `codex_exec.log` — полный лог работы Codex.
- `codex_last.md` — финальный ответ модели.
- `report.md` — итоговый отчет.

## 5. Отчеты и прозрачность
Каждый цикл публикует отчёт в Telegram:
- что запланировано,
- что подготовлено,
- какие действия были выполнены,
- сколько задач в работе,
- время начала и завершения.

Таким образом видно, что система **реально работает**, а не просто «крутится в фоне».

## 6. Глубокие задачи и редактирование кода
Редактирование кода разрешено, но:
1. **Каждая задача уходит в отдельную ветку** (если git репозиторий инициализирован).
2. **Merge только по инициативе оркестратора.**
3. Любые правки фиксируются в `report.md`.

Если git не инициализирован, ветки не создаются, и агент пишет предупреждение в событиях.

## 7. Как добавить свою задачу
В Telegram:
```
/task Заголовок | Описание
```

Локально:
```
python - <<'PY'
import sys
from pathlib import Path
repo = Path.cwd()
sys.path.insert(0, str(repo / "code"))
from agent.queue import enqueue_task
enqueue_task({
    "type": "custom",
    "title": "Мой таск",
    "description": "Что нужно сделать",
    "needs_agent": True,
})
PY
```

## 8. Контроль качества
Каждая задача обязана оставить:
- артефакт в workspace,
- запись в `events.jsonl`,
- запись в daily summary (если значимая).

Если артефакта нет — задача считается сомнительной.

## 9. Типичные проблемы
**Нет `report.md`:**
- проверь `codex_exec.log`,
- проверь, что `codex exec` не упал,
- посмотри `codex_last.md`.

**Задачи не идут:**
- проверь `runner.py watch`,
- проверь `queue.json`,
- проверь `events.jsonl`.

**Окна Codex открываются, но «ничего» не происходит:**
- проверь `codex_exec.log`,
- возможно Codex работает в фоне.
